# Help an author write a profile

Read this only when a person asks for help writing a profile. Work toward a draft mission, ask the author to confirm it, and keep it as a vault snippet as `MISSION-FORMAT.md` says. Use no word of this skill without a plain gloss.

With a document, anything that says what a learner should be able to do, capture it as a source first with its text stored. For a document on disk, run `capture --type source --url file://<absolute path> --content-file <path> --store-body --ack-data-egress`. Say that the address of such a source is a path on the machine that captured it, and that in the one trial `refresh` answered `unreachable` for it, with `refused non-https url: file://`. Show the author the part of the document that was read. Propose a draft from it, say what the document did not give, and say that more documents can be given.

Ask one item in each turn through the host's question dialog when one exists:

1. Who is the profile for?
2. What must a learner be able to do at the end? Ask for things a person could watch.
3. What is out of scope?
4. Which options should it set? Point at the table in `MISSION-FORMAT.md`.
5. Should it come with a path? If so, ask for its lessons in order, written with every term taken as new.

Offer the vault's subjects as `SKILL.md` section 2, item 2 does. Never ask the author what a learner knows.

Show the changed draft before asking the author to confirm it. Say what happens after: you capture the profile as a snippet, a learner can start from it, and this skill lets the learner adjust any part of it. An author who wants one fixed course builds the workspace and exports it.
