## Decisions

### D0. Contracts kept

1. The Shapes table, `SHAPES`, `LESSON_SHAPE_BLOCK_MISSING` and the Plan-before-probe rule are untouched: the fact block stays required where it is required. The issue's alternative, dropping it beside an example, is not taken.
2. The two labels stay. `lesson.mjs` does not read a block's label, but the format requires each lesson's `aria-label` to carry it and argocd 0001 does, and a rename touches two fixtures, `reading.html`, the format's table and both built workspaces' stylesheets, for a word; the sequence is shown by stacking (D2) and said by the format (D1) and the reading page (D4).
3. The quiz-beside-step pair is out of scope, as the issue says.
4. No lint for "below" or "above" between fact and example: D2 stacks the two, so with fact before example in source order (where the Shapes table and lesson 0001 put them) the words are expected to hold between them at every width, which D6's rendering checks, and there is nothing to report. Quiz beside step stays, and words between those two are out of scope with the pair.

### D1. The fact block's purpose and length

The `fact` row's Holds cell becomes: "What the probe established, one cited claim per `<p>`, two to five `<p>` of one or two sentences each, every `<p>` ending in a citation anchor. Beside an `example` block it is the summary read first; the example is the walkthrough of the same run, so the fact block does not retell it and the model block does not narrate it." The `## Prose` section gains: "`fact` comes before `example` in source order and `lesson.css` spans both from 1100px, so the two are stacked at every width and "below" and "above" between them hold."

### D2. The layout and the colours

In `lesson.css`: line 142 becomes "Two columns from 1100px: quiz beside step; everything else spans, fact above example."; line 145 gains `[data-block="fact"], [data-block="example"]`; lines 108 and 109 are deleted and line 73's content becomes "what the lab showed", so the fact block takes `--c-fact` again (the model's colour, the two blocks the Thread check reads as one story) and the example block keeps `--c-example`. Lines 110 and 111 stay.

### D3. The reader

`agents/lesson-reader.md` check 2 becomes "Do the model, fact and example blocks tell one story a reader can follow from the first paragraph to the last, or are they a list of true sentences, or the same run told twice? Name the paragraph where the thread breaks or the retelling starts and what question the reader is left with." Line 12 is unchanged: the reader reads source order and cannot see the columns, so D2 is checked by rendering (D6).

### D4. Documents that restate the behaviour

- `SKILL.md` line 72: "lays fact beside example and quiz beside step from 1100px wide" becomes "stacks fact above example and lays quiz beside step from 1100px wide".
- `reading.html` line 29 becomes "What the run established, in short: one cited claim per paragraph, read before the example block, which walks through the same run."
- `scripts/deps.mjs`: one row tying `LESSON-FORMAT.md` to `lesson.css` for the stacking sentence (literal `1100px`).
- `CHANGELOG.md`: one line under `## [Unreleased]`, `### Changed` (line 10).
- Not changed: the fixtures, `lesson.mjs`, the Shapes table, the labels.

### D5. Tests

1. `test/lesson-reader.test.mjs`: the body holds "the model, fact and example blocks tell one story".
2. `test/teach-store.test.mjs`: `lesson.css` holds, inside the 1100px media rule, a span rule naming `[data-block="fact"]` and `[data-block="example"]`, and no rule setting the fact block's colour to `--c-example`.

### D6. The argocd workspace

Done after the plugin change, in the workspace, not committed anywhere (no repository): copy the plugin's `lesson.css` over `assets/lesson.css` (identical today, so `cp` not `cp -n`); rewrite lesson 0001's fact block as four `<p>` of one or two sentences each, the first opening with the sentence that orders the two blocks ("in the order the example below walks through them"), one claim per paragraph with the anchors it has now (the apply agrees; the hand scale opens a gap that nothing in the cluster closed in the ten seconds observed and `kubectl diff` exits 1; a re-apply closes it and a deleted pod is replaced by the Deployment's controller, which works from `spec`; the final diff exits 0 and a GitOps controller runs that compare-and-apply against Git), with no time word and no retelling; leave the model block's "the diff below", the example's "the step's commands below" and the step's "the Terminating listing above", which source order is expected to make true once fact and example are stacked (the diff output, the step's commands and the Terminating listing sit in the example and step blocks, after the model block and before the step block's words), the expectation the rendering below checks; run `teach lint --prose`; a reader round through a fresh agent carrying the D3 text (every installed plugin copy lacks the spec 36 checks); a claims round on the changed block through the `research-claims-gate` skill, recorded in the workspace's ledger and gate log; and a rendering of the page with `firefox --headless --screenshot` at window widths 1280, 1100 and 900 (1280 clearly above the breakpoint, since a scrollbar can take a 1100 window below it), read back and captured as an experiment, to show fact above example at each.
