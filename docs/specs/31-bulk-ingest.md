## Decisions

### D0. Contracts kept

1. A JSON-array plan behaves as today: `runBatch` keeps its signature and stays synchronous, with the same dedup, the same `{ errors, created, skipped }`, and nothing written on any error unless `--continue` is given.
2. The network stays double-gated: an ingest from a URL list refuses unless `RESEARCH_VAULT_ALLOW_NETWORK=1` is set, as `refresh` does, and uses the same `fetchSource`, so the SSRF rules, HTTPS-only, re-validated redirects, body cap and timeout apply unchanged. `fetchSource` also returns `body` (the buffered bytes); `refreshVault` reads only `status` and `hash`, so `refresh` stores nothing, as before.
3. Body egress stays double-gated: `--store-body` with `--ack-data-egress` at the CLI stores the fetched or read text in each source; without them only `content_hash` is written. `--store-body` without `--ack-data-egress` is the per-spec error `prepareEntry` throws today.
4. Not built: a rate limit (one request per line, sequential, as `refresh`), HTML-to-text conversion (the stored body is the raw response text, so `content_hash` is what `refresh` computes over the same bytes), and any metadata beyond the title, the URL and, for a Markdown file, `source_author` from its frontmatter (`captured_via` stays the caller's).

### D1. Three inputs

The validation-and-write loop of `runBatch` (from the manifest read to the result) moves into `runSpecs(vaultPath, specs, cliOpts)`, synchronous; `runBatch` becomes the JSON read plus `runSpecs`, so its callers and tests are untouched. A new `export async function ingest(vaultPath, path, cliOpts)` builds the specs for the two new inputs and returns `runSpecs(vaultPath, specs, cliOpts)`, or the index -1 result below. `run` decides by the path: a directory goes to `ingest` as a Markdown directory, a path ending in `.json` to `runBatch` as today, any other file to `ingest` as a URL list; `run` awaits `ingest`. Both new inputs produce source specs that go through the existing `specToOpts`, `prepareEntry` and write loop, so dedup, `skipped` and the manifest rebuild are the same code. `specToOpts` keeps a spec's own `content` and `contentBytes` when it has no `contentFile`, and passes `sourceAuthor`; `prepareEntry` gains one line, `if (opts.sourceAuthor) data.source_author = opts.sourceAuthor;`, beside `captured_via`.

- URL list: one URL per line; blank lines and lines starting with `#` are dropped; `index` is the position among the kept lines. `fetch` is `cliOpts.fetch`, else `fetchSource` when `cliOpts.allowNetwork`, else the result is `{ errors: [{ index: -1, error: 'network access is off: set RESEARCH_VAULT_ALLOW_NETWORK=1 to ingest a URL list' }], created: [], skipped: [] }`. For each line, `await fetch(url, {})`; a thrown error or a `status` of 400 or more is `{ index, error: 'fetch failed: <message or http <status>>' }` and no spec; otherwise the spec is `{ type: 'source', title, url, contentBytes: body, content: body.toString('utf8'), storeBody: cliOpts.storeBody }`, `title` being the text of the first `<title>` element (whitespace collapsed) or, when there is none, the URL.
- Markdown directory: every `*.md` directly in the directory, sorted by name, `index` its position. The file's text is read; when it starts with `---` and parses, `source_url` or `url` from the frontmatter is the URL, `title` from the frontmatter the title, and `author` or `source_author` from it the `sourceAuthor`; otherwise the URL is the target of the first `](https://...)` or `](http://...)` link, and the title the first `# ` heading's text; a title still missing is the file name without `.md`. A file with no URL is `{ index, error: 'no source URL: <file>' }`. The spec is `{ type: 'source', title, url, contentBytes: <the file's bytes>, content: <the file's text>, storeBody: cliOpts.storeBody }`.
- `--continue`: a new `BOOL` flag. In `runSpecs`, a spec is pushed to `pending` only when it collected no error (today a spec whose only error is an unresolved reference is still pushed, which is harmless because nothing is written). After the validation pass, `runSpecs` returns without writing when `errors` is non-empty and `cliOpts.continue` is not set; with it set, the pending specs are written and the errors reported beside `created`. A spec that references the id of a failed spec is then the unresolved-reference error, and is not written. The issue's rule is that the flag "applies only to specs with no references to other specs in the plan"; this plan narrows it: a spec whose references all resolve, to the vault or to a sibling that is written, is written under `--continue`, since its reference is sound, and only a reference to a failed sibling withholds it.

`run` passes `{ ackDataEgress, storeBody: !!args['store-body'], continue: !!args.continue, allowNetwork: process.env.RESEARCH_VAULT_ALLOW_NETWORK === '1', fetch: typeof args.fetch === 'function' ? args.fetch : undefined }` to both, and prints and exits as today (exit 1 when `errors` is non-empty, under `--continue` too).
