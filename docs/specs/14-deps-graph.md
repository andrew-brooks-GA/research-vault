# Spec 14: a derived dependency graph for the plugin repo

Round 6 (2026-10-27). A seven-agent inventory of the repo at a151aa6 (experiment 2026-10-27-seven-agent-dependency-inventory-research-vault) merged 831 edges of 14 kinds over 189 nodes; 313 of those edges, 38%, originate in a markdown, YAML or JSON file rather than in code, and the readers reported 135 couplings that no path reference connects (copied values, printed strings, name contracts). A 32-line prototype of the extractor was run at a151aa6 and against a scratch copy with five injected breaks (experiment 2026-10-27-dependency-graph-prototype-run-five-mutation), and `node --test` was run against the same kinds of break (experiment 2026-10-27-does-node-test-at-research-vault). The repo lines this spec relies on are quoted at a151aa6 in the snippets 2026-10-27-research-vault-repo-lines-cited-by and 2026-10-27-spec-14-second-gate-round-hook. The Claude Code facts come from the hooks reference 2026-10-26-claude-code-hooks-reference and the best-practices note 2026-10-26-claude-code-plugin-best-practices-hooks. This spec is the executable list for the next session.

## Problems

1. A markdown-to-code edge has no check. Renaming `bin/lib/stale.mjs` makes `node --test` fail (18 failures, `ERR_MODULE_NOT_FOUND`), but four breaks that keep every module in place left 405 of 405 tests passing: an agent whose frontmatter `name` changes while its file keeps its path (the skills still dispatch the old name), a misspelled flag in `commands/research-init.md`, and a renamed script name in `.github/workflows/ci.yml` and in `AGENTS.md`. A handful of such edges have a hand-written assertion each: `test/hooks-config.test.mjs` checks that every hooks.json script path exists and carries a numeric timeout, `test/skills.test.mjs` checks that the claims-gate skill body contains `subagent_type: research-vault:claims-reviewer`, `test/manifests.test.mjs` checks that package.json and plugin.json carry the same version.
2. This spec adds a reverse-dependency query: given a file, the files that import, read, test, document, invoke or are declared coupled to it.
3. The inventory found drift between hand-copied values, which no path check can see: the authority-basis list at line 17 of `skills/research-capture/SKILL.md` lacks `tool-output`, which `schema/taxonomy.json` includes and which line 12 of the same skill uses; step 1 of `vault-template/meta/prompt-templates/verify-entry.md` says `last_verified` is the max of all verification dates, while `vault-template/meta/freshness-policy.md` and `CONFIRMING_RESULTS` in `bin/lib/manifest.mjs` count only `confirmed` and `changed-trivially`; `agents/claims-reviewer.md` keys on a `Changed units:` line while `bin/commands/gate.mjs` prints `changed units:`.
4. `schema/project-config.schema.json` is read by nothing in the repo; the validator is `parseProjectConfig` in `bin/lib/projectconfig.mjs`. The `taxonomy.json` that `init` copies into a vault is read by the CLI only as an existence marker (`VAULT_MARKERS` in `bin/commands/init.mjs`); `loadSchema` reads the bundled `schema/taxonomy.json` plus the project's `taxonomy_extensions`. The vault copy is agent-facing (the generated vault AGENTS.md points at it) and is left alone.
5. `AGENTS.md` tells a contributor to run `npm run lint:self`, and `.github/workflows/ci.yml` does not run it.

## Design

### D1. `scripts/deps.mjs`: the graph is computed on every run, never stored

One ESM file, no dependencies, no classes. It exports `build()` and runs its CLI only under the guard all four hooks use, `if (process.argv[1] && import.meta.url.endsWith(process.argv[1].replace(/\\/g, '/').split('/').pop()))`, so a test can import it. `scripts/check-agentsmd-drift.mjs` is not the model here: it has no export and calls `process.exit` at top level.

**Universe.** Files from `git ls-files -z --cached --others --exclude-standard`, run with `cwd` set to the repo root derived from `import.meta.url`, filtered by `existsSync`. So a new file joins the moment it exists, a plain `mv` does not crash the script, and `docs/specs/` and `GATE-LOG.md`, both listed in `.gitignore`, never enter. `.gitignore` gains `ci-vault/`, the untracked directory the CI steps create, so a local run of those steps does not add it to the universe. `CHANGELOG.md` is excluded from every extractor, because release history legitimately names removed files (`commands/research-advise.md`, for one). Node ids are the files plus `cli:<cmd>` for every key of the `commands` map in `bin/research-vault.mjs` and `npm:<script>` for every key of `scripts` in `package.json`. An edge is `{ from, kind, to }`, deduplicated on all three. An edge is ok when `to` is a node id; a `reads` edge is also ok when `to` is a directory prefix of some file (`join(repoRoot, 'schema', f)` with a variable tail yields `schema`).

**Extractors.** Every `to` is built with forward slashes (`path.posix`), because CI runs on Windows. `EXTRACTED` and `IGNORED` are two exported sets of file extensions; every extension in the universe must be in one of them (asserted in D2), so a new file type forces a decision instead of silently contributing no edges.

- `import`, `tests` (`.mjs`, `.js`): a relative specifier in `from '...'` or `import('...')`, resolved against the importer's directory; kind `tests` when the importer is under `test/`. Catches the dynamic command map in `bin/research-vault.mjs`.
- `reads` (`.mjs`): a quoted `'schema'` or `'vault-template'` followed by further quoted segments, with no `join(` anchor (an anchor would not see the read in `bin/lib/manifest.mjs`, whose `join(` is followed by `dirname(`); and any single-quoted string literal that starts with a top-level directory and ends in an extracted extension (this is how `test/skills.test.mjs` reads `skills/research-teach/LESSON-FORMAT.md`).
- `registers` (`hooks/hooks.json`): every `${CLAUDE_PLUGIN_ROOT}/<path>`.
- `documents` (`.md`, `.yml`, `.json`, and the extensionless `bin/research-vault` shim; not `hooks/hooks.json`, which `registers` covers): a token with left boundary `(?<![\w./-])`, starting with a top-level directory of the universe (dot-directories included), ending in `.mjs`, `.js`, `.md`, `.json`, `.yml`, `.css` or `.html`, and containing none of `* ? < > {`; a relative markdown link target `](x)` resolved against the file's directory; a bare root filename that is a node (`SECURITY.md`, `LICENSE`); and a `meta/...` path, which means the template file, mapped to `vault-template/meta/...`. Bare basenames in prose ("edit stale.mjs") are deliberately not resolved: they are ambiguous.
- `invokes-skill`, `invokes-agent`, `invokes-command` (`.md`): `research-vault:<name>` anywhere, and any backticked `` `/?research-<name>` `` other than `research-vault`. The name resolves against the frontmatter `name:` of `agents/*.md` and `skills/*/SKILL.md` (not the file name: the suite catches a renamed module, `bin/lib/stale.mjs`, and misses a renamed `name:`) and against the basenames of `commands/*.md`; the matching file becomes `to`, so `deps.mjs agents/claims-reviewer.md` lists the skills that dispatch it. A name in none of the three sets is a broken edge of kind `invokes-unknown`.
- `invokes-cli` (`.md`, `.yml`, `.json`), counted only inside a code span, a fenced block or a YAML/JSON string, never in running prose ("the research-vault plugin", "research-vault gives" are not invocations): the forms `research-vault <cmd>`, `research-vault.mjs <cmd>`, `research-vault.mjs" <cmd>` (the quoted `${CLAUDE_PLUGIN_ROOT}` form in `commands/*.md`), and a span or fenced line whose first word is a key of the `commands` map (`gate evidence <draft> --extra <ids> --changed`, `check --check <draft>`, the way the skills write them). Subcommand words may follow the command; every `--flag` in the span is checked. The edge is `from -> cli:<cmd>`, plus `cli:<cmd> -> bin/commands/<cmd>.mjs` (kind `dispatches`) so a reverse query on a command module reaches the prose. A word after the `research-vault` prefix inside code that is not a command key is a broken edge. The flag set for `<cmd>` is every `args.<flag>` and `args['<flag>']` read in `bin/commands/<cmd>.mjs` and in the `bin/lib` modules it imports directly (the depth-1 import edges), excluding matches followed by `.mjs` (the `./lib/args.mjs` specifier). A `ponytail:` comment names the two ceilings: a flag read by a shared lib module is accepted for every command importing it, and a boolean flag missing from `BOOL` in `bin/lib/args.mjs` is not detected.
- `npm` (`.md`, `.yml`): `npm run <script>` becomes `from -> npm:<script>`.
- `couples`: a committed `COUPLINGS` array in the script, one `[a, b, why]` row per pair of files that depend on each other through something other than a path (a copied value, a printed string, a name contract, a format), emitted as an edge in both directions. It is seeded from the 135 hidden couplings in the inventory experiment, keeping the rows whose two ends are repo files (a row whose end is a glob or a concept is not a row). D2 fails when either end leaves the universe, so a row cannot rot by path, and a reverse query on `bin/lib/stale.mjs` then lists `vault-template/meta/freshness-policy.md` with its reason. This list is the one hand-maintained part of the graph, and D3 says when to add to it.
- Not extracted: `generates` (`schema/AGENTS.golden.md` has its own drift check) and `env` (template literals make it noise).

**CLI**, from any directory:

- `node scripts/deps.mjs` prints every broken edge as `<kind> <from> -> <to>` and exits 1 if there are any.
- `node scripts/deps.mjs <id>` prints the distance-1 dependents of a file, `cli:<cmd>` or `npm:<script>`: one line per dependent, `<kinds> <from>` with kinds comma-joined when a pair carries more than one, and `why` appended for a `couples` edge. Depth is 1. `traverse` from `bin/lib/graph.mjs` was considered and dropped: at depth 1 the lookup is one `filter`, and at depth 2 or more the walk passes through `bin/research-vault.mjs`, which imports every command module, and from there reaches whatever names the dispatcher.
- `node scripts/deps.mjs --hook` reads a PostToolUse event from stdin, takes `tool_input.file_path` relative to the repo root, and when that file has dependents prints `{"hookSpecificOutput":{"hookEventName":"PostToolUse","additionalContext":"Files that depend on <path>: ..."}}`, the shape `hooks/post-tool-use.mjs` emits. Factual text only, per the hooks reference. Silent when there are none; exit 0 always; any error is swallowed.

### D2. `test/deps.test.mjs`: CI fails on a broken edge

1. `build().broken` is empty; the test builds its own failure message listing every offending edge with kind, from and to, which is the change checklist for whoever broke them.
2. A sample table: one input string per supported syntax (a `from` import, a dynamic import, a `with { type: 'json' }` import, the three CLI prefix forms, a bare command span with a subcommand, a `research-vault:<name>`, a backticked `/research-<name>`, a relative markdown link, a `meta/` path, a `${CLAUDE_PLUGIN_ROOT}` path, an `npm run`, a `'schema', 'x.json'` read) and the edge each must yield, run through an exported `extract(file, text)`. A regex that stops matching one form fails its row. There are no count floors: a floor on a whole kind lets one form die unseen (the inventory critic counted 278 relative import pairs).
3. Every extension in the universe is in `EXTRACTED` or `IGNORED`.

It is a `test/*.test.mjs` file like the other 45 and runs under the existing `node --test` step, on ubuntu, macos and windows with Node 22 and 24. No change to `ci.yml` for D1 or D2.

### D3. Two sentences in `AGENTS.md`

Under `## Rules`: "Before renaming or removing a file, a CLI flag, a skill, an agent or an npm script, run `node scripts/deps.mjs <path>` (or `cli:<command>`) and update every dependent it lists; `npm test` fails on a reference to something that no longer exists. When a change makes two files depend on each other through anything other than a path (a copied value, a printed string, a name, a format), add a `COUPLINGS` row in `scripts/deps.mjs`."

### D4. A project hook that shows the blast radius

`.claude/settings.json`, committed, with one PostToolUse handler, matcher `Edit|Write`, command `node scripts/deps.mjs --hook`, timeout 10. The hooks reference lists `.claude/settings.json` as the single-project settings file that can be committed to the repo, and lists a plugin's `hooks/hooks.json` as bundled with the plugin and run whenever the plugin is enabled; this hook belongs to the repo, so it must not go in `hooks/hooks.json`. This repo's `.gitignore` currently ignores `.claude/` as a whole, so the line becomes `.claude/*` followed by `!.claude/settings.json`. The hooks reference also records that a `PostToolUse` hook matching `Edit|Write` does not run when a `Bash` command rewrites the file; the hook is a convenience, D2 is the enforcement. The rule in D3 stays, because the hook cannot see a change the agent makes through the shell.

### D5. Hand-written edge tests stay

`test/hooks-config.test.mjs`, `test/skills.test.mjs`, `test/agent.test.mjs` and `test/manifests.test.mjs` assert more than existence (timeouts, frontmatter fields, version equality). The overlap between `hooks-config.test.mjs` and the `registers` edges is intended; neither is a duplicate of the other.

### D6. Drift fixes from the inventory, with the regression tests that make them stick

- `skills/research-capture/SKILL.md`: add `tool-output` to the authority-basis list. Test: every value of `authority_basis` in `schema/taxonomy.json` appears in that skill's text.
- `vault-template/meta/prompt-templates/verify-entry.md` step 1: `last_verified` is the latest verification date whose result is `confirmed` or `changed-trivially`, matching `freshness-policy.md` and `CONFIRMING_RESULTS`. Test: both template files contain both result words on the `last_verified` line.
- `agents/claims-reviewer.md`: `changed units:` in lowercase. Test: the literal the gate prints appears in the agent body.
- Delete `schema/project-config.schema.json`. Nothing reads it, no test or doc names it.
- `.github/workflows/ci.yml`: append `- run: npm run lint:self` as the last step, after check-encoding. It must not take `--check`: on a checkout with no `vault-template/.vault-manifest.json`, `lint --vault vault-template --check` prints `MANIFEST_STALE` and exits 1. The manifest it writes is gitignored.
- CHANGELOG: one `[Unreleased]` line plus an "Upgrading an existing vault" note for the verify-entry.md change, since `refreshDocs` in `bin/commands/init.mjs` writes only AGENTS.md and copies taxonomy.json.

## How the graph stays maintained as the repo grows

- Nothing to regenerate. The graph is derived from the working tree on every run. There is no committed graph and so no graph drift. The committed, reviewable parts are the `COUPLINGS` list and the D2 sample table; a change to either shows in a diff.
- New files join by themselves. The universe is the working tree; the `documents` prefixes, the skill, agent and command names, the CLI commands, the npm scripts and the per-command flags are all derived from files. Adding any of them needs no edit to the graph. A new file extension fails D2 until it is put in `EXTRACTED` or `IGNORED`.
- A new way of referencing things is one regex and one sample row. The sample table is what keeps every existing form alive; a form that stops matching fails its row the same day.
- Couplings are declared where they are created. D3 makes the `COUPLINGS` row part of the change that creates a coupling; D2 fails when a coupled file disappears; the D4 hook shows the row to the next agent that edits either side.
- The failure is the checklist. When a rename breaks the test, the output names exactly the files to update.
- Known ceiling. The graph checks that referenced things exist and that declared couplings still have both ends. It does not check that prose describes behaviour correctly, that a copied value is still equal, or that a flag is in `BOOL`. Equality of copied values is covered one pair at a time by D6-style tests, and generating the hand-copied enum lists from `schema/` the way the golden is generated is the next spec.

## Plan

Two branches, each committed locally and gated, pushed as branches so CI runs the Windows job before anything reaches master, then merged locally and pushed. No pull request.

1. `feat/deps-graph` off master: D1, D2, D3, D4, a CHANGELOG line under `[Unreleased]`. Before each commit: `npm test`, `npm run lint:self`, `node scripts/check-agentsmd-drift.mjs`, `node scripts/check-encoding.mjs`. Acceptance on the branch head: `node scripts/deps.mjs` prints nothing and exits 0; the five mutations of the prototype experiment on a scratch copy (rename `agents/claims-reviewer.md` to `agents/claims-checker.md`; rename `bin/lib/stale.mjs` to `bin/lib/staleness.mjs`; `--refresh-docs` to `--refresh-doc` in `commands/research-init.md`; `scripts/check-encoding.mjs` to `scripts/check-encodings.mjs` in both `.github/workflows/ci.yml` and `AGENTS.md`) each produce at least one broken edge naming the mutated reference, the `ci.yml` one included; so does the break the `node --test` experiment adds to the prototype's five, the agent's frontmatter `name` changed with its file kept; `node scripts/deps.mjs bin/lib/stale.mjs` lists exactly the eight importers and two tests of the prototype experiment plus the `couples` rows; `node scripts/deps.mjs cli:init` lists exactly `README.md`, `commands/research-init.md`, `docs/MIGRATION.md` and `skills/research-authoring/SKILL.md`.
2. `fix/inventory-drift` off `feat/deps-graph`, not off master, so the CHANGELOG line and the gated files do not conflict or need re-gating after a rebase: D6.
3. Claims gate per branch, following `skills/research-claims-gate/SKILL.md`: capture the repo lines the changed prose cites as one snippet at the branch head, then gate `docs/specs/14-deps-graph.md` and `AGENTS.md` on branch 1, and `skills/research-capture/SKILL.md`, `agents/claims-reviewer.md` and the two template files on branch 2. Not `CHANGELOG.md`: `check CHANGELOG.md` reports its two links (keepachangelog, semver) as uncovered, which stops the gate at its citations step, and, per the comment on `unitHashes` in `bin/lib/gate.mjs`, a markdown file without data-block elements is one unit, so every release line would be re-verdicted. Two reviewer rounds at most, then the skill's MERIT verdict. `gate status <file> --check` must pass for every gated file before merge.
4. Push both branches, wait for CI green on all six jobs, then on master: `git merge --no-ff feat/deps-graph`, `git merge --no-ff fix/inventory-drift`, run the four checks, `git push origin master`.
