## Decisions

### D0. Contracts kept

1. Advisory only: a new `advise` key computed from the log and the manifest, nothing in `lint --check`, no new write; the command stays read-only (2026-11-02-lines-behind-issue-6-hit-rate, the librarian skill line 20, REFERENCE line 201).
2. The log is the only input. The issue's sentence that "#15 always logs the query's topic" holds for `search` only, and there only when `--topic` carries a value: a pre-web event names no topic (D1 counts it for `surfaced`, never for a topic). A topic is counted under the value `search` logged, as typed; aliases are not resolved.
3. `readUsage` becomes tolerant: a line that does not parse is skipped, as `ledgerRows` in `gate.mjs` skips one, so a damaged log never stops `advise`, nor the post-edit hook's citation logging, whose `readUsage` call sits inside a `try` whose `catch` swallows any throw (2026-11-02-lines-behind-issue-6-hit-rate, `gate.mjs` lines 128 to 132, `post-tool-use.mjs` lines 53 to 60, the `readUsage` probe).

### D1. `listUsage`

`advise.mjs` imports `readUsage` and gains `listUsage(vaultPath, m)`, returned as the thirteenth key, `usage`, an object:

- `entries`: for every manifest row with at least one count, ordered by id, `{ id, surfaced, cited }`: `surfaced` is the number of `queried` events whose `ids` contain the id (either writer), `cited` the number of `cited` events whose `id` is the id. An id in the log that is not a manifest row is ignored.
- `topics`: an object keyed by every `topic` value found on a `queried` event, each `{ queried, noMatch }`: the number of such events and, of those, the number whose `outcome` is `no-match`.
- `cold`: `{ queried, unqueried }`, two id lists over the rows of type `source` whose `status` is not `superseded` and whose `cited` count is zero, in manifest order: `queried` holds those with at least one topic that is a key of `topics`, `unqueried` the rest. A vault with no log has empty `entries` and `topics` and every live source under `cold.unqueried`.

The command prints four lines after the near-duplicates line: `usage (<n>): <id> (surfaced <s>, cited <c>), ...`; `topics queried (<n>): <topic> (<q> queried, <m> no-match), ...`; `cold sources under a queried topic (<n>): <ids>`; `cold sources never queried (<n>): <ids>`; each list `—` when empty. `--json` carries the object unchanged.

### D2. The librarian's bullet

`skills/research-librarian/SKILL.md`: "thirteen sections" and a bullet **usage** after **near duplicates**: per entry how often the pre-web hook or `search` surfaced it and how often a watched file cited it, per `--topic` value how often `search` was asked and how often it found nothing, and the cold sources (live, never cited) split by whether one of their topics was ever asked for; computed from `_index/usage.jsonl`, so a vault without the log shows every live source as never queried. The judging step is unchanged.
