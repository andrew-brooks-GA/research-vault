## Decisions

### D0. Contracts kept

1. Nothing enters `lint --check`; the key is advisory, in `advise`, as the issue says.
2. Siblings with different versions are not listed: they are the succession the verify skill prescribes.
3. The semantic judgment (two live entries whose claims conflict) stays with the agent, as one step in the librarian skill.
4. No new frontmatter field, manifest key or lint code.

### D1. `supersedeSuspects`

`advise.mjs` gains `listSupersedeSuspects(m)`: over the manifest rows whose `status` is not `superseded`, every pair of rows of the same `type` whose `verKey(subject?.version)` is equal on both and where either both `source_url` values are non-null and equal (`by: 'source_url'`, which is `capture`'s own dedup key, url plus version), or both `subject.name` values are non-empty and equal (`by: 'subject'`). Two unversioned entries compare equal on version; a versioned one against an unversioned one does not, so a same-URL pair at versions `1` and `2` is a succession, not a suspect. A pair matched on both fields is listed once, as `source_url`. Each pair is `{ older, newer, by }`, `older` being the row that sorts first (the earlier id), in row order. `verKey` moves from `capture.mjs` to `ids.mjs` as an export and both files import it, so nothing is copied and no `COUPLINGS` row is needed. The scan is a pair loop over the live rows, marked with a `ponytail:` comment naming the index-by-field upgrade. `advise` returns it as an eleventh key, `supersedeSuspects`.

The command prints one more line after the open-question line: `supersede suspects (<n>): <older> -> <newer> (<by>), ...`, or `—`.

### D2. The librarian's step

`skills/research-librarian/SKILL.md`: "eleven sections", a bullet **supersede suspects** (pairs of live entries of one type with the same `source_url`, or the same subject name at the same version or both unversioned; the older first), and one judging step after the section list: for each pair, open both entries; if they state the same claim, `verify --id <older> --method cross-referenced --result outdated --superseded-by <newer>` (`cross-referenced` is in `verification_method`: 2026-11-02-lines-behind-issue-8-supersede-suspects, round 1 additions, the `taxonomy.json` grep); if they describe different versions, give each its `subject.version` (the pair then leaves the list, whichever field paired it); if both are current and say different things, add each to the other's `related` and capture a `question` naming them, as the capture skill's conflict review at its line 9 does (2026-11-02-lines-behind-issue-8-supersede-suspects, round 1 additions). The step judges; the command only pairs.
