# Spec 18: hygiene bundle, a manifest shrink guard, a dangling-edge report, the reviewer's hash in the ledger row, and the topic vocabulary for search

Round 3 (2026-11-01), on master at ecfd2fb (the lines this spec names are quoted in snippet 2026-11-01-spec-18-lines-at-research-vault). This is item 3 of evaluation 16's ranked plan, "Hygiene from lens one and two, as a single small change: manifest shrink guard, reviewer-prompt hash in the ledger row, `manifest --topics` and the vocabulary rule in `research-vault-usage`" (`docs/specs/16-graphify-evaluation.md` §5, quoted in 2026-11-01-spec-18-lines-at-research-vault). The four come from three rows of evaluation 16's table, which "names the concepts in Graphify-Labs/graphify worth re-deriving for this plugin" under the rule "take the concept, not the code or the feature" (its line 3, quoted in 2026-11-01-spec-18-lines-at-research-vault); nothing of graphify's code or features is ported. Today's behaviour on the inputs this spec changes was probed and recorded (experiments 2026-11-01-probe-manifest-rebuild-writes-shrunken-manifest, 2026-11-01-probe-claims-ledger-row-holds-ts and 2026-11-01-probe-edited-reviewer-agent-file-leaves; the first and third print the commit in their Result, the second names it in its frontmatter). ## Decisions this spec designs within

Taken in evaluation 16 and not reopened here, each from the row of its table quoted in 2026-11-01-spec-18-lines-at-research-vault: the shrink guard is "refuse to write a manifest with fewer entries than the last one unless the entry files are actually gone, and report dangling edges before writing" (the row "Shrink guard and health gate before writing a derived index"); the ledger change is "Add the agent definition's hash to the row so a changed reviewer invalidates old verdicts. Small, in the spirit of the existing design" (the row "Extraction cache keyed by content hash and prompt file"); and the search change "lives in the skill, not the CLI: the usage skill should tell the agent to read the topic vocabulary (a `manifest --topics` listing is a one-line addition) and choose search terms from it. Auditability comes free because the agent prints its search commands" (the row "Constrained query expansion"). Also the repo's own rules, quoted from `AGENTS.md`: "ESM only, no dependencies, no classes. Keep a change small and in the style of the code around it", and a `COUPLINGS` row when two files come to depend on each other through anything other than a path. And the integration contract: `docs/REFERENCE.md` says of the manifest's and `check --json`'s keys "These keys are the integration contract: `test/contract.test.mjs` pins them, and a change is a breaking one in the CHANGELOG", and `test/contract.test.mjs` asserts the manifest's top-level keys and, per entry, the field list `ENTRY` (its lines 11-21, quoted in 2026-11-01-spec-18-lines-at-research-vault), so nothing here adds a key to the manifest or an entry row.

One consequence made explicit so it is not read as drift: a ledger row written before this spec carries no reviewer hash (2026-11-01-probe-claims-ledger-row-holds-ts), and such a row keeps its standing (D3). Treating it as void would reopen every unit of every gated file at once, a retroactive re-audit this spec declines: a verdict is reopened by an edit to the file or, from now on, to the reviewer, never by the arrival of this field. The next verdict on each file carries the hash, and from then on a change to the reviewer reopens that file.

## Problems

1. `manifest --rebuild` writes what it built with no check of its size against the file already there. `writeManifest` in `bin/lib/manifest.mjs` serialises the manifest it is given (or builds one from the vault when none is passed) to `.vault-manifest.json.tmp` and renames it over `.vault-manifest.json`, and does not read the existing `.vault-manifest.json` first; `walkEntries` in `bin/lib/fsutil.mjs` skips a type folder that does not exist (`if (!existsSync(dir)) continue;`) (both quoted in 2026-11-01-spec-18-lines-at-research-vault). Probed at ecfd2fb, one shrink from two entries to one, on a copy of the test suite's fixture vault (one source, one synthesis): `manifest --rebuild` printed `manifest: 2 entries`; with `synthesis/` moved out of the vault it printed `manifest: 1 entries`, exit 0, and the file on disk then listed one entry, `2026-01-01-a`; with the folder moved back, `lint --check` reported `MANIFEST_STALE` and exited 1 (2026-11-01-probe-manifest-rebuild-writes-shrunken-manifest). Nothing refused the shrinking write, and the file is what an outside consumer reads: REFERENCE's section "Reading the graph from outside" (lines 149-156) names `<vault>/.vault-manifest.json` as one of the two outputs a project with its own graph reads, and the usage skill's §1 step 2 says "Retrieve via `.vault-manifest.json`" (both quoted in 2026-11-01-spec-18-lines-at-research-vault).
2. A dangling edge is written without a word. `buildManifest` pushes an edge `{ from, rel, to }` for every non-empty, not-yet-seen value of every edge field and never checks that `to` names an entry (lines 48-54, quoted in 2026-11-01-spec-18-lines-at-research-vault). Probed at ecfd2fb with a note whose `sources` names `2026-01-09-missing`: `manifest --rebuild` printed `manifest: 3 entries`, exit 0, and the manifest on disk carried the edge `{"from":"2026-01-03-dangling","rel":"sources","to":"2026-01-09-missing"}`; `lint` reported `DANGLING_REF  <scratch>/vaultA/notes/2026-01-03-dangling.md: sources -> missing id 2026-01-09-missing` and exited 1, and still rewrote the manifest (its mtime moved from 1793546687 to 1793546688; three entries on disk after) (2026-11-01-probe-manifest-rebuild-writes-shrunken-manifest). `lintAndReport` in `bin/commands/lint.mjs` (its line 10) calls `writeManifest(vaultPath)` on every run without `--check`, whatever the violations (quoted in 2026-11-01-spec-18-lines-at-research-vault); `lint --check` on the same vault reports the same `DANGLING_REF` and exits 1 (2026-11-01-probe-edited-reviewer-agent-file-leaves).
3. A verdict outlives the reviewer that gave it. `recordVerdict` in `bin/lib/gate.mjs` writes `ts`, `event`, `file`, `sha256`, `verdict`, `units` and, when given, `note`; `gateStatus` takes the last row for the file whose `sha256` is the current content's and whose verdict is `PASS` or `MERIT`, else falls back to the units covered by any such row through `changedUnits` (lines 104-147, quoted in 2026-11-01-spec-18-lines-at-research-vault). Probed (the run is 2026-11-01-probe-claims-ledger-row-holds-ts, whose frontmatter names ecfd2fb): a `PASS` row carried exactly `ts`, `event`, `file`, `sha256`, `verdict` and `units`, a `MERIT` row with a note added `note`, and `gate status --check` passed on the `PASS` row (2026-11-01-probe-claims-ledger-row-holds-ts). Nothing in the row names the agent that reviewed. Probed at ecfd2fb: a copy of the plugin with one line appended to `agents/claims-reviewer.md` (sha256 08ec5a96... in the repo, c009f09b... in the copy), run against that ledger, printed `docs/d.md: MERIT @ a77934cae1c3` for `gate status --check`, exit 0, and `MERIT (by unit)` after a blank line was appended to the draft (2026-11-01-probe-edited-reviewer-agent-file-leaves): the edit to the agent file, whose frontmatter pins `model: opus` and `effort: high` and whose body is the review procedure (quoted in 2026-11-01-spec-18-lines-at-research-vault), left the earlier verdict standing in the probe, and nothing in `gateStatus` or `changedUnits` reads the agent file (the snippet's lines 104-147).
4. `search` is literal, and the agent has no list to choose from. `searchVault` in `bin/commands/search.mjs` filters `--topic` by equality after alias expansion and `--text` by substring of title, topics and summary, and drops superseded entries unless `--include-superseded` (lines 10-22, quoted in 2026-11-01-spec-18-lines-at-research-vault). `--topics` is not in `BOOL` in `bin/lib/args.mjs` (quoted in 2026-11-01-spec-18-lines-at-research-vault); probed at ecfd2fb, `manifest --topics --vault <vault>` and `manifest --vault <vault> --topics` each printed the full JSON manifest, exit 0 (2026-11-01-probe-edited-reviewer-agent-file-leaves, P3; the first form also in 2026-11-01-probe-manifest-rebuild-writes-shrunken-manifest). The usage skill's §1 step 2 tells the agent to route single-fact questions to `search` and says nothing about where its terms come from (quoted in 2026-11-01-spec-18-lines-at-research-vault).

## Design

### D0. Contracts the implementation keeps

1. **The manifest's shape.** `buildManifest(vaultPath)` keeps its one-argument signature and returns the same four keys and the same entry fields; `test/contract.test.mjs` goes on asserting them unchanged. The dangling-edge report is computed from the manifest, not stored in it.
2. **`lint` keeps `DANGLING_REF`.** The lint rule (`bin/lib/lintrules.mjs` line 129, quoted in 2026-11-01-spec-18-lines-at-research-vault) is the violation; `manifest --rebuild`'s report (D2) says the same thing in the command that writes the file, and neither replaces the other.
3. **The ledger stays append-only JSONL, and old rows stand.** A row without `reviewer` is read as it is today (D3).
4. **No new command.** `--topics` is a flag on `manifest`, so the `--help` usage line `test/smoke.test.mjs` asserts (its lines 6-12 and the coupling row at `scripts/deps.mjs` line 28, quoted in 2026-11-01-spec-18-lines-at-research-vault) is unchanged, and `manifest` still "only writes with `--rebuild`" (REFERENCE line 198, quoted there).
5. **`search` is unchanged.** The vocabulary rule lives in the skill, as evaluation 16 decided.

### D1. The shrink guard in `writeManifest`

Before writing, `writeManifest` reads the manifest already at `<vault>/.vault-manifest.json`; when there is none, or it does not parse, there is nothing to guard and the write proceeds. For each entry listed in that file and absent from the new manifest, the entry is *gone* when its type folder (`TYPE_FOLDER[type]` of `bin/lib/fsutil.mjs`) exists under the vault and `<folder>/<id>.md` does not: the author deleted the file. Any dropped entry that is not gone, because its folder is missing or its file is still there, makes `writeManifest` throw

```
manifest not written: it would drop 1 listed entry that is not gone (2026-01-02-b: synthesis/ is missing); remove <vault>/.vault-manifest.json to accept the shrink
```

with the count, the first such id and its reason (`<folder>/ is missing` or `<folder>/<id>.md still exists`), and the file on disk is untouched. Every caller gets the guard, since it is in the function: `manifest --rebuild`, `lint` (without `--check`), `capture`, `verify` and `init` all call `writeManifest` (the `grep -rn writeManifest` block in 2026-11-01-spec-18-lines-at-research-vault); the CLI's catch prints `error: <message>` and sets exit code 2 (`bin/research-vault.mjs` lines 27-35, quoted there). Deleting the derived file is the override, and the message says so; no flag, since the file is derived and the vault template's `.gitignore` lists it (quoted in 2026-11-01-spec-18-lines-at-research-vault), and a flag would be a second way to say the same thing.

The rule is the folder-level reading of evaluation 16's "unless the entry files are actually gone". On a full rebuild from the file system, `walkEntries` lists every `.md` file but `INDEX.md` in each existing type folder and `buildManifest` pushes one entry per listed file (`bin/lib/manifest.mjs` lines 28-47, quoted in 2026-11-01-spec-18-lines-at-research-vault), so a listed entry whose file is present drops only when the walk and the write see different directories, which this spec does not try to explain further; a whole folder's entries drop when the folder is absent, which is the probe's case. Ordinary deletion, one file at a time with the folder in place, is accepted without ceremony.

### D2. The dangling-edge report in `manifest --rebuild`

`danglingEdges(manifest)` in `bin/lib/manifest.mjs` returns the edges whose `to` is not an entry id, in manifest order. `manifest --rebuild` prints, on stderr and before writing, one header line and one line per edge:

```
manifest: 1 dangling edge(s)
  2026-01-03-dangling --sources--> 2026-01-09-missing
```

then writes as today and prints `manifest: N entries`, exit 0. The manifest is still written because the lint rule (D0 rule 2) already fails `lint` and `lint --check` on the reference (both probed: 2026-11-01-probe-manifest-rebuild-writes-shrunken-manifest and 2026-11-01-probe-edited-reviewer-agent-file-leaves), and a manifest with the edge is the fuller picture while the author fixes it; this report makes the writing command say what is wrong at the moment it writes. `lint`'s own run is unchanged: it already names the file and the field.

### D3. The reviewer's hash in the ledger row

`recordVerdict` adds `reviewer`: the sha256 of the bytes of `agents/claims-reviewer.md` under the plugin root (`REPO_ROOT` at `bin/lib/gate.mjs` line 21, quoted in 2026-11-01-spec-18-lines-at-research-vault), bare hex like `sha256`; when that file is absent the field is omitted. The agent file is the reviewer: its frontmatter pins the model and effort and its body is the review procedure (lines 1-12, quoted in 2026-11-01-spec-18-lines-at-research-vault), so an edit to any of them is a different reviewer, and the hash covers the whole file.

A row counts, in `gateStatus`'s exact-bytes match, in `changedUnits`'s per-unit coverage and therefore in the `(by unit)` fallback, only when its verdict is `PASS` or `MERIT` and its `reviewer` is absent or equals the current hash. One predicate in `bin/lib/gate.mjs` replaces the three `SATISFIES.has(r.verdict)` tests (lines 117, 139 and 144 at ecfd2fb, the whole file's uses after the set's definition: the `grep -n SATISFIES` block in 2026-11-01-spec-18-lines-at-research-vault), so the three readers cannot disagree. When no row counts but a `PASS` or `MERIT` row for the file carries another hash, `gate status` prints `none (reviewer changed)` in place of today's `none` (`bin/commands/gate.mjs` lines 29-32 and 68-72, quoted in 2026-11-01-spec-18-lines-at-research-vault; an unrecorded file prints `docs/u.md: none @ 1de034877457`, 2026-11-01-probe-edited-reviewer-agent-file-leaves), so a file that was covered yesterday and is not today says why; `gate staged` prints the same token in place of its `none`. The row written before this spec has no `reviewer` and keeps standing (the consequence stated above).

The `COUPLINGS` row between `bin/lib/gate.mjs` and `agents/claims-reviewer.md` (quoted in 2026-11-01-spec-18-lines-at-research-vault) has its `why` extended to say that `recordVerdict` hashes the file into the `reviewer` field.

### D4. `manifest --topics`

`--topics` takes no value. `topics` cannot join `BOOL` in `bin/lib/args.mjs`, because `capture --topics a,b` reads the flag as a value (`bin/commands/capture.mjs` line 208, quoted in 2026-11-01-spec-18-lines-at-research-vault); `parseArgs` records a flag at the end of the line or followed by another `--` flag as a key with the value `undefined` (`bin/lib/args.mjs` lines 4-19, quoted there), so the command tests for the key's presence, and REFERENCE says the flag takes no value. `manifest --topics` prints one line per distinct topic over the entries whose `status` is not `superseded`, which is the set `search` sees by default, as `<topic> <count>` sorted by topic, exit 0, and writes nothing. Topics are listed as written in the entries; aliases from `taxonomy.topic_aliases` (`tdd` and `ci` today, quoted in 2026-11-01-spec-18-lines-at-research-vault) are not folded: `searchVault` passes the query and each entry's topics through the same `expand` (the snippet's search.mjs line 20), and for `tdd`, probed at ecfd2fb with one entry tagged `tdd` and one `test-driven-development`, `--topic tdd` and `--topic test-driven-development` each returned both (2026-11-01-probe-edited-reviewer-agent-file-leaves, P5). With `--rebuild` as well, the rebuild happens first and the list replaces the JSON print; without either flag, `manifest` prints the JSON as today.

### D5. The vocabulary rule in the usage skill, and REFERENCE

`skills/research-vault-usage/SKILL.md` §1 step 2 gains, after "Route first: single-fact questions use `search` only.": `search` matches literally (`--topic` by equality after alias expansion, `--text` as a substring of title, topics and summary), so take terms from the vault's own vocabulary: `manifest --topics` lists every topic in use with its entry count; choose `--topic` values from that list, and when the list has no term for the question say so rather than inventing a synonym; the search commands run are the audit trail of the choice.

`docs/REFERENCE.md`: the `manifest` row of the command table gains `--topics` and the two `--rebuild` behaviours (the dangling-edge report and the refused shrink, with the override); the "Gate" paragraph at line 44 gains the `reviewer` field, the rule that a row counts only while its reviewer hash is absent or current, and that rows written before this change carry none and keep standing. "Reading the graph from outside" is unchanged, since the keys are.

### D6. Not done here

No guard on `_index/` and `_obsidian/`: evaluation 16's row names them, and they stay unguarded by design: `compile` and `obsidian` build from `buildManifest`'s return value and write their folders without `writeManifest` (`bin/commands/compile.mjs` lines 7-11, `bin/commands/obsidian.mjs` lines 33-36, quoted in 2026-11-01-spec-18-lines-at-research-vault), so D1's guard does not reach them; both are browsing views regenerated in full on every run, neither is one of the two outputs REFERENCE names as the contract, and a guard there would be a second copy of D1 for a file nothing joins on. No `--force`: removing the derived file is the override. No change to lint's `DANGLING_REF` or to its writing the manifest after a violation. No hash of anything but the claims-reviewer agent file: the skill that dispatches the reviewer with the prompt and records the verdict (`research-claims-gate`, its steps 2 and 4, quoted in 2026-11-01-spec-18-lines-at-research-vault, the latter in its round-3 block) is the caller, and the row records who judged. No alias folding or ranking in `--topics` or `search`: evaluation 16 kept `search` literal and put the fix in the skill. No re-gating of existing rows (the consequence stated above). No `check --json` change and no manifest key, so the contract test and the examples are untouched.
