## Decisions

### D0. Contracts kept

1. A vault without an `embedding` block in its repo's binding is unchanged: `search` without `--semantic` runs as today, `embed` and `search --semantic` refuse with `no embedding endpoint in .research-vault.json`, and no file is written.
2. Sending text to the endpoint is a third outbound path, after `refresh` and the URL-list ingest, and a body egress, so both commands need `RESEARCH_VAULT_ALLOW_NETWORK=1` (the gate `refresh` uses) and `--ack-data-egress` (the acknowledgement `export` uses); either missing refuses with exit 1 before any request.
3. The endpoint is the operator's explicit choice and may be local, so the request goes through the global `fetch`, not the `refresh` fetcher, whose SSRF guard refuses non-public hosts; `SECURITY.md` says so.
4. The index is a disposable cache, `_index/embeddings.jsonl` in the vault, which the template's `.gitignore` already ignores; nothing else is written besides the usage-log line `search` already appends to `_index/usage.jsonl`. No dependency is added.

### D1. The binding block

`embedding: { url, model?, chunk?, overlap? }` in `.research-vault.json`: `url` a string that parses as an `http:` or `https:` URL, `model` a string when present, `chunk` and `overlap` integers when present (`chunk` at least 1, `overlap` at least 0 and below `chunk`; defaults 800 and 100). `parseProjectConfig` validates it with messages of the `invalid .research-vault.json: embedding.<key> ...` form and returns it as `embedding`, absent when the block is absent.

### D2. `embed.mjs` and the `embed` command

`bin/lib/embed.mjs` exports `INDEX` (`_index/embeddings.jsonl`), `embedTexts(cfg, texts, { fetch })`, `cosine(a, b)` and `readIndex(vaultPath)`. `embedTexts` sends one `POST` to `cfg.url` with `Content-Type: application/json`, an `Authorization: Bearer <RESEARCH_VAULT_EMBED_KEY>` header when that variable is set, and the body `{ input: texts, model: cfg.model }`; a non-2xx status throws `embedding endpoint <status>`; the vectors are read from `data[i].embedding` or, failing that, `embeddings[i]`, the two response shapes accepted, and a count other than `texts.length` throws. `fetch` defaults to `globalThis.fetch`. `readIndex` returns `null` when the file is absent, else `{ header, rows }` from the first line and the rest.

`research-vault embed [--ack-data-egress]`: after the D0.2 refusals, it builds `buildExport(vaultPath, { scope: <the six `TYPE_FOLDER` types>, includeBodies: true, ackDataEgress: true, chunk, overlap })`, drops the windows of entries whose manifest `status` is `superseded`, embeds the window texts in batches of 64 (sequential requests, no rate limit) and writes the index: a header line `{ url, model, dimensions, chunk, overlap, built }` then one line per window `{ id, chunk, text, vector }`. It prints `embedded <windows> windows of <entries> entries into _index/embeddings.jsonl` and returns 0. `--json` is not added. The command is appended after `teach` in the CLI's `USAGE` line and `commands` map, so the smoke test's pattern, which stops at `manifest`, is unchanged by it.

### D3. `search --semantic <text>`

In `search`'s `run`, `--semantic <text>` with the D0.2 refusals plus `search refused: no embedding index; run embed first` when `readIndex` returns `null`: the rows are `matchRows` over the manifest with the usual facets, superseded rows always dropped; the query is embedded with one request; each row's score is the highest cosine over its windows, multiplied by `STALE_WEIGHT` (0.8) when `staleness` reports the row stale (a `ponytail:` note names the knob); rows with no window are left out; the hits are sorted by score, descending, and cut to `--limit` (default 10). The text line is the ordinary search line followed by `score <two decimals> #<window index>`; `--json` prints the rows with `score` and `chunk` added. The usage event gains `semantic: true` and carries the query under `text` only when `usage.text` is set, as today. `--semantic` is not combined with `--sort`, `--text` or `--body` (each refused with a message).
