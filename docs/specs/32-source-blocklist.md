## Decisions

### D0. Contracts kept

1. The list is a vault file, `meta/source-blocklist.json`, as the issue decided: `init --refresh-docs` never touches `meta/` and the template ships no list, so an absent file is an empty list. The schema and the binding are untouched.
2. `lint --check`'s exit code is unchanged by a match: a match is a warning. A list that does not parse or has a malformed row is a violation, since a silent empty list would unblock everything.
3. `capture` refuses before the dedup check, so a blocked URL is never reported as a duplicate; `--force` is the single-capture override only. A plan key named `force` is ignored, so in `--batch` a match is the item's error, as the issue says.
4. `captured_via` stays the caller's; the override is recorded in the `captured` seed verification's `notes`, as the issue says.

### D1. `blocklist.mjs`

`bin/lib/blocklist.mjs` exports `BLOCKLIST` (`meta/source-blocklist.json`), `loadBlocklist(vaultPath)` and `matchBlock(rows, url)`. `loadBlocklist` returns `[]` when the file is absent; otherwise it parses the file and throws `invalid meta/source-blocklist.json: <why>` unless it is an array whose every row has a non-empty string `pattern`, a `scope` of `url` or `domain` and a non-empty string `reason` (`added` is free text, the date the row was added). `matchBlock` returns the first row that matches the URL, or `null`: a `domain` row matches when the URL parses and its host, lower-cased, equals the pattern or ends with `.` and the pattern; a `url` row matches when `normalizeUrlSafe(url)` starts with `normalizeUrlSafe(pattern)`. A URL that does not parse matches no `domain` row.

### D2. The three placements

- `capture.mjs`: `prepareEntry` gains, after the `source requires url` line, `const hit = opts.type === 'source' ? matchBlock(loadBlocklist(vaultPath), opts.url) : null; if (hit && !opts.force) throw new Error(`blocked source: ${hit.pattern} (${hit.scope}): ${hit.reason}; --force captures anyway`);` and the seed verification's `notes` becomes `hit ? `captured with --force past the blocklist: ${hit.pattern} (${hit.scope}): ${hit.reason}` : ''`. `specToOpts` sets `force: false` after the spread. `run` passes `force: !!args.force` to `captureEntry` and is otherwise unchanged: a blocked single capture throws from `prepareEntry` through `captureEntry` (lines 118 to 126, no catch) and `run`, and the dispatcher prints `error: blocked source: ...` with exit code 2, as it does for `source requires url`.
- `lintrules.mjs`: `lintVault` loads the list once; a throw from `loadBlocklist` is the violation `BLOCKLIST_INVALID` on the list file with the message, and the list is then empty for the run. Per source, a match is `warn(abs, 'WARN_SOURCE_BLOCKED', `source_url matches the blocklist: ${pattern} (${scope}): ${reason}`)`. `fixVault` is unchanged.
- `pre-web.mjs`: `vaultContext` computes `hit` for a `WebFetch` URL (`matchBlock(loadBlocklist(vaultPath), toolInput.url)`, inside a `try` that leaves `hit` null on a throw) and, when it is set, prepends `research-vault: this URL is on the vault's source blocklist (${pattern}, ${scope}): ${reason}.` to whatever it would have returned, joined by a newline, so the captured-already line still follows for a listed URL that is also captured. The usage-log event is unchanged.
