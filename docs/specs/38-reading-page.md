## Decisions

### D0. Contracts kept

1. No new route: the page is a static file under `assets/`, served by the existing `STATIC_DIRS` rule as `text/html`, not passed through `footnoteCitations` (it is not under `/lessons/` or `/reference/`).
2. No placeholder convention, as the issue decided: the page describes the `$` prompt and the withheld mark, nothing that would collide with the rule that a `step` states a command exactly as the experiment quotes it.
3. The lesson-reader is not told about the page: `lesson-reader.md` line 10 and its test are untouched.
4. `cp -n` stays, so an edited copy in a workspace is left alone; the copy now runs on every lesson build, so a workspace built before this spec receives the page at its next lesson.

### D1. The page

`skills/research-teach/assets/reading.html`: a static page titled "How to read a lesson", linking `lesson.css` (`<link rel="stylesheet" href="lesson.css">`, since it sits beside it) and loading no script. Its body holds `<h1>How to read a lesson</h1>` and sections with `data-block` names so the stylesheet labels them as a lesson would: one per block label in the format's table, in the table's order (`prereq`, `mission`, `predict`, `model`, `fact`, `example`, `quiz`, `complete`, `scaffold`, `step`, `connect`, `sources`, `followup`, `note`), each holding one paragraph saying what the label asks of the learner; then, as plain prose under a final section `data-block` set to `reading` (which the fallback rule labels `reading`), the `$` prompt (a line starting with `$ ` is a command; the lines after it are its output), the withheld mark (the blank in a `do it yourself` command is the part to supply), the `[n]` numbering (a bracketed number is a source, numbered by its place in the sources block, and a link when served) and the follow-up reminder (the `followup` block's sentence, that follow-up questions go to the terminal).

### D2. The copy, the links and the rows

- `SKILL.md` step 4 becomes "On every lesson build, from the workspace root (the first build creates `assets/`; a later one delivers a file the workspace lacks and leaves an edited copy alone):" and its `cp -n` line gains `"${CLAUDE_PLUGIN_ROOT}/skills/research-teach/assets/reading.html"`.
- `indexHtml` emits `<p class="reading-link"><a href="/assets/reading.html">How to read a lesson</a></p>` between `<h1>Lessons</h1>` and the index section; the store test's two regexes do not depend on what precedes the section, so they still match.
- `renderNav` appends `link('/assets/reading.html', 'How to read', 'lesson-nav-reading')` after the "Progress" link.
- `scripts/deps.mjs`: a row tying `reading.html` to `LESSON-FORMAT.md` for the label list (literal `say it back`), beside row 107, and a row tying `teach.mjs` to `reading.html` for the index link's path (literal `reading.html`); `quiz.js` to `reading.html` likewise (literal `reading.html`).
