## Decisions

### D0. Contracts kept

1. The log lives at `_index/usage.jsonl` in the vault, a path the template's `.gitignore` already ignores and `SKIP_DIRS` already skips, so no entry walk sees it; an older vault whose `.gitignore` lacks `_index/` adds the line by hand, as the issue says.
2. Append-only, one JSON object per line, written by the two hooks and by `search`; no frontmatter field, no manifest key.
3. Every event holds ids, facets and an outcome; free text (the pre-web terms and `search --text`) is written only when the binding sets `usage.text` to `true`. There is no other opt-out: the log is local, derived and ignored by git, and the hooks and `search` already see the same data.
4. A log failure never changes what a hook or `search` prints: every append is wrapped.

### D1. `usagelog.mjs`

`bin/lib/usagelog.mjs` exports `USAGE_LOG` (`_index/usage.jsonl`), `appendUsage(vaultPath, event)`, which makes `_index` if needed and appends one line, `JSON.stringify({ ts: <ISO timestamp>, ...event })`, and `readUsage(vaultPath)`, the parsed lines in order, `[]` when the file is absent. `parseProjectConfig` accepts `usage.text`, a boolean, else `invalid .research-vault.json: usage.text must be a boolean`, and returns `usage` with the rest.

### D2. The three capture points

- `vaultContext(vaultPath, toolName, toolInput, opts = {})` appends one `queried` event after computing its answer: `{ kind: 'queried', via: 'pre-web', tool: toolName, outcome, ids }`, `outcome` being `url-hit` (ids: the one entry), `hits` (ids: the listed entries) or `no-match` (ids empty), plus `text: terms.join(' ')` when `opts.text` is true; the returned string is unchanged. The main block passes `{ text: cfg?.usage?.text === true }` from `loadProjectConfig` of the event's `cwd`.
- `citationWarnings`, for a watched file in its citation branch, resolves each citation to an id as `checkCitations` does (an `id` citation as itself, a `url` citation through the manifest row whose `source_url` equals `normalizeUrl` of its value) and appends one `{ kind: 'cited', via: 'post-tool-use', file: key, id }` per id that `readUsage` holds no `cited` event for under that file; that is the "newly" test the issue describes, since the hook keeps no state of its own. The returned string is unchanged; code and versions files append nothing.
- `search`'s `run` appends one `{ kind: 'queried', via: 'search', type, topic, outcome, ids }` after `searchVault`, `type` and `topic` the flag values (absent when not given), `outcome` `hits` or `no-match`, `ids` the rows' ids, plus `text: args.text` when the nearest binding above the working directory sets `usage.text` and `--text` was given.
