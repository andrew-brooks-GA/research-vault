## Decisions

### D0. Contracts kept

1. `capture` stays create-only; closing an existing question is a `verify` mode, since `verify` is the command that already edits an entry in place and the duplicate message points at it.
2. No verification row is appended by the close: a verification records a check of the entry's own claim, and the question's claim is not checked, its state changes.
3. No new frontmatter field, manifest key or lint code: `state`, `answer_summary` and `contributing` exist, `DANGLING_REF` and `WARN_ANSWERED_NO_SUMMARY` already police them.
4. The threshold is a constant, 60 days as the issue proposed; the age comes from the id's date prefix, since a manifest row has no creation date.
5. Candidate matching by shared subject and topics stays out, as the issue says.

### D1. `advise` lists open questions past 60 days

`advise.mjs` exports `OPEN_QUESTION_DAYS = 60` and `advise` returns a tenth key, `openQuestions`: for each manifest row with `type` `question`, `status` `active` and `state` other than `answered`, the age in days is the whole number of days from the id's first ten characters to `now`, and the row is listed as `{ id, state, ageDays }` when `ageDays` is greater than `OPEN_QUESTION_DAYS`. The order is the manifest's, by id. No file is read: the row's `type`, `status`, `state` and `id` suffice.

The command prints one more line after the quote-residue line: `open questions over 60 days (<n>): <id> (<state>, <ageDays>d), ...`, or `—` when the list is empty; the number in the label is `OPEN_QUESTION_DAYS`, imported from the library. `--json` carries the new key with the rest.

### D2. `verify --id <question> --answered-by <id> [--answer-summary <text>]`

`verify.mjs` exports `answerQuestion(vaultPath, { id, answeredBy, answerSummary, now, repoRoot })`. It loads the schema with `vaultPath`, finds the entry with `findEntry` (so a missing id throws `entry not found: <id>`), throws `not a question: <id>` when the entry's `type` is not `question`, and finds the answering entry with `findEntry` too (any type; `contributing` targets `any`), so a missing answering id throws before anything is written. Then it sets `state` to `answered`; sets `answer_summary` to `answerSummary` when given, else to the answering entry's `summary` when that is a non-empty string, else leaves the field as it is (and `lint` warns `WARN_ANSWERED_NO_SUMMARY` as today); sets `contributing` to the existing list plus `answeredBy`, deduplicated; sets `updated` to `now` (the day, as `applyVerification` computes it); calls `assertControlledValues`; writes the entry with `writeEntry` in `fieldOrder` and calls `writeManifest`; and returns `{ action: 'answered' }`.

`run` takes the branch when `args['answered-by']` is set, after the `--stale` branch and `reportFallback`, with `answerSummary: args['answer-summary']`, and prints `verify: answered`. `--method` and `--result` are not read in that mode. `flagsOf` sees `args['answered-by']` and `args['answer-summary']` in `verify.mjs`, so `extract` adds no `cli:verify --answered-by` or `cli:verify --answer-summary` edge for the documented invocations.
